# 失败模式词典（格式 + 维护规则）

> Agent 写代码默认覆盖 happy path，对历史 bug 与边界缺乏先验。本词典把真实 bug 沉淀成可 sweep 的先验。**条目是项目专属的**（如 atlas 的 SQL 优先级、桶排序）——本 skill 提供**格式 + 维护规则 + 空表**，项目的 F-1..F-N 写在项目 AGENTS.md「项目专属失败模式词典」节。

## 维护规则

- **写新功能 / 写测试前必须 sweep**：逐条问「我的代码会不会踩这个？」可能 → 必须有对应测试。
- **每出一次真 bug**：复盘最后一步来项目词典加一条。
- **删条目**：需在 MR description 写明 `modify-failure-dict: <reason>`。
- 每条最高信号的是从**实际失败**沉淀的具体症状 + 测试范式，不是通用原则（对应 Anthropic「Gotchas 段最高信号」）。

## 条目模板（出 bug 后追加用）

```markdown
#### F-<项目缩写>-N · 一句话病征

- **症状**：xxx（具体到能让人 grep 出自己代码里的同型）
- **来源**：commit hash / MR 链接 / 复盘文档
- **测试范式**：unit + 端到端两层各举 1 例（写出断言形态）
- **触发场景**：什么改动时要警觉地查这条（PR 关键词 / 改了哪类代码）
```

## 空表（项目侧填充）

```markdown
## 项目专属失败模式词典
> 格式继承团队 skill agent-spec-failure-mode-dict。每出一次真 bug 追加一条；写新功能必须 sweep。

（暂无条目——出第一个真 bug 后按上方模板追加）
```

## 候选条目（跨项目高频，命中后转正到项目词典）

以下是 nexus-fe 多项目常见的失败模式**候选**，**不预填进项目词典**，等项目真实命中后按模板转正：

- 全局响应拦截器误包装二进制 / 流 / SSE 响应。
- DTO 格式校验通过 ≠ 业务校验通过（开放重定向 / SSRF / 越权）。
- 状态机新增分支后，旧测试里断言旧状态的 case 静默失效（改状态机必须同 MR sweep 所有断言该状态的测试）。
- 反向代理拓扑下，基于 `remoteAddress` 的 IP 守卫语义失真（从外部测守卫的外部行为，不假设内部判断）。
